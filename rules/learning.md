# 自我學習迴圈 (Self-Learning Loop) — 全域

跨所有專案的自我學習機制：任務中擷取教訓 → 蒸餾成精煉記憶 → 升級為規則／技能／決策紀錄 → 定期修剪與驗證。本檔為**權威定義**，各專案的 learning 規則只做專案特化補充、不重複本檔內容。架構參考〈AI Agent 7 層架構〉(<https://raymondhouch.com/lifehacker/digital-workflow/ai-agent-7-layer-architecture/>)。

儲存格式與 `skills/learn`、`skills/evolve` 完全同構：**索引 + 個別 frontmatter 檔**，不分全域/專案層，差別只在路徑。全域與專案層皆不再使用暫存 inbox 中介層——`learn` 擷取時直接寫入對應記憶檔並更新索引，成本已經夠低，不需要「先進 inbox、再定期蒸餾」這道手續。

## 0. 每個 session 開場

- 若 `~/.claude/memory/MEMORY.md`（全域通用記憶索引）存在，**先讀取**再開始任務——這是跨專案的「便利貼」層。
- Claude Code 已自動注入當前專案的 per-project 記憶索引（`~/.claude/projects/<專案>/memory/MEMORY.md`）；不必再手動讀索引本身，但索引指到的 `overview.md`（若存在）須依 `claude-workflow/WORKFLOW.md` §1 的規定，在判定軌別前主動讀取。
- 兩層記憶都是「當下觀察」，引用前需確認仍成立（見 §7）。

## 1. 迴圈總覽

```text
擷取 (Capture) → 蒸餾 (Distill) → 升級 (Promote) → 修剪 (Prune) → 驗證 (Verify) ─┐
   ▲                                                                            │
   └────────────────────────────────────────────────────────────────────────────┘
```

- **擷取**：任務中即時把教訓寫入對應記憶層（索引 + 個別檔），成本低、不打斷任務，不經暫存中介。
- **蒸餾**：`learn`／`evolve` skill 檢視近期記憶檔，去重、概括、視需要升級——`evolve` 隨時可執行，不綁定固定週期。
- **升級**：重複出現或結構性的教訓，升級成規則／技能／決策紀錄，成為永久行為。
- **修剪**：刪除過時、被證偽、已升級的個別記憶檔與對應索引行，維持索引精簡。
- **驗證**：檢查既有教訓是否真的阻止了重複錯誤；無效教訓必須改寫或升級，不得原樣留著。

## 2. 擷取觸發（always_on）

任務進行中遇到下列任一情況，**必須當下**依 `learn` skill 的格式寫入對應記憶檔並更新索引（§4 分流、§5 格式）：

1. 使用者糾正了你的做法、答案或假設。
2. 出現編譯／測試／執行錯誤，且根因是可概括的錯誤假設（而非一次性筆誤）。
3. 發現實際行為與文件／規則的描述不符，或發現專案的歷史脈絡、架構緣由與既有認知不符。
4. 同一 session 內第二次犯同類錯誤。
5. 使用者明說「記住」「記錄教訓」「下次注意」（此時改用 `learn` skill 完整處理）。
6. 專案任務收尾（輕軌 L4／標準軌 M4／重軌 R6）——依 `claude-workflow/WORKFLOW.md` §9「know-how 沉澱」三問檢查，這是本迴圈在專案記憶層的機械化收口，權威定義在該檔、本處不重複。

**例外**：教訓若屬方案取捨的設計決策，且該專案有決策紀錄機制（如 ADR／`docs/decisions/`），直接走該機制；記憶層只記一行指標指回該決策，不重複內容。

## 3. 記憶分層與分流

| 教訓性質 | 去向（記憶層） |
|---|---|
| **跨專案通用**：協作偏好、工具鏈陷阱、通用流程與方法論 | 全域 `~/.claude/memory/`（`MEMORY.md` 索引 + 個別記憶檔） |
| **專案特定**，且該專案有 repo 內記憶層（如 `.agent/learning/`） | 該專案 repo 內記憶層（跨 agent、進版控優先） |
| **專案特定**，該專案無 repo 內記憶層 | Claude Code 內建 per-project 記憶（`~/.claude/projects/<專案>/memory/`，`MEMORY.md` 索引 + 個別記憶檔 + `overview.md` 聚合檔） |

判斷原則：**這條教訓換一個專案還成立嗎？** 成立→全域；只在此專案成立→專案層。拿不準時先進專案層，`evolve` 時再視是否跨專案重複判斷要不要升級全域。

**技術性教訓（工程踩坑／設計模式）不另開系統**：像「Redis 寫入忘了設 TTL」「cache 多入口沒同步失效」這類技術踩坑，本質上也是「專案特定」或「跨專案通用」教訓的一種，一樣走上表分流，不建立獨立的 knowledge base。差別只在於：technical 類教訓在記憶檔裡應標註涉及的技術/模組（方便日後同類問題搜尋），見 §4.2 的「技術 playbook」升級路徑。

**專案歷史脈絡與關注點的特殊分流**：架構演進緣由、「為什麼長這樣」這類敘事性知識，不切成個別記憶檔，聚合進專案記憶層的 `overview.md`（結構定義見 `claude-workflow/WORKFLOW.md`「專案記憶層結構」）；`overview.md` 是索引「導覽」區的固定入口，不受本節「教訓」分流表管轄。

## 4. 蒸餾／升級／修剪規則

### 4.1 蒸餾（記憶檔的持續整理）

- 觸發：使用者執行 `learn`／`evolve`；或執行 `evolve` 時發現同一記憶層下個別記憶檔數量偏多、內容重疊。
- `learn` 擷取時已直接寫入格式化記憶檔（frontmatter + 三段式內容），不需要「先寫粗略草稿、再蒸餾成精煉版」這道額外工序；`evolve` 的蒸餾工作聚焦在**去重與合併**，而非格式轉換。
- 全域 `MEMORY.md` 索引行數上限 **50 行**；專案 `overview.md` 內容上限**約 100 行**。任一逼近上限時，`evolve` 必須先修剪或升級，禁止無限成長。

### 4.2 升級（記憶 → 規則／技能／決策紀錄）

| 教訓性質 | 去向 |
|---|---|
| 每個任務都該遵守的準則，或同類教訓重複 ≥2 次 | 規則檔：跨專案→`~/.claude/rules/`；專案內→該專案規則（如 `.agent/rules/`） |
| 多步驟可重複的程序（「如何做某件事」） | 新增／更新 skill：跨專案→`~/.claude/skills/`；專案內→該專案 skills |
| 方案取捨、架構決策 | 該專案決策紀錄機制（如 ADR）；無則記在專案記憶層 `DECISIONS.md` |
| 同一技術域（如 Redis、WebSocket、快取）累積 **3～5 條**技術性教訓 | 蒸餾成一份「技術 playbook」：一份文件彙整該技術域的設計決策流程 + 必過檢查清單 + 已知坑速查，放在教訓所屬的記憶層（跨專案→全域 `~/.claude/memory/`；專案特定→該專案的記憶層，同上表判斷），檔名建議 `playbook-<技術域>.md`，並在對應 `MEMORY.md` 索引加一行 |

升級後，原個別記憶檔**刪除**、索引對應行**移除或改為一行指標**（指向新位置），避免雙重維護與內容漂移。技術 playbook 是活的：新教訓屬於某 playbook 的技術域時，同一次更新順手在該 playbook 補一列檢查項並連回來源，不要另開新記憶檔與 playbook 內容重複。

**與 ADR 的分工**：ADR 記「為什麼這樣決定」（一次性決策的理由與被拒方案）；技術 playbook 記「下次碰到這個技術，照這個做／別踩這個坑」（可複用的操作型知識）。同一個事件可能同時觸發兩者——例如「改用 XX 快取策略」值得寫 ADR 記錄取捨理由，同時如果踩到了「快取沒設 TTL」這種技術坑，也值得累積進對應技術 playbook。

### 4.3 修剪

- `evolve` 時逐條驗證：記憶檔引用的檔案／指令／行為是否仍存在（用讀檔工具實際確認，不憑印象）；過時或被證偽的記憶檔與其索引行直接刪除。
- 某教訓記錄後同類錯誤仍再度發生 → 該記憶檔視為**無效**，必須升級為規則或 skill 並改寫，不得原樣保留。
- 專案 `overview.md` 每次 `evolve` 一併校準：內容是否仍與現況相符、是否超過約 100 行需把細節下放個別記憶檔（只留索引行）。

## 5. 檔案格式

記憶檔格式（全域與專案層同構，與 Claude Code 內建 auto-memory 一致）：

```markdown
---
name: <short-kebab-case-slug>
description: <一行摘要>
metadata:
  type: user | feedback | project | reference | pitfall
---

<內容；feedback/project 類需含 **Why:** 與 **How to apply:**>
```

`pitfall` 類內文模板（三段缺一不可）：

```markdown
**錯誤情境:**<當時怎麼錯的：錯誤的寫法/理解，與它造成的後果>

**正確做法:**<修正後的寫法/理解>

**避坑檢查點:**<下次遇到什麼訊號要警覺；可操作的檢查動作>
```

索引檔（`MEMORY.md`）固定用 `- [標題](file.md) — 一行摘要` 一行一筆，依性質歸類分區（例如：協作偏好／環境與工具陷阱／流程教訓／專案事實）；新增/刪除記憶檔時同步維護對應索引行。

`DECISIONS.md` 條目模板（決策流水帳，append-only）：

```markdown
## YYYY-MM-DD 一句話標題
- **背景**：當時的情境與遇到的問題
- **決策**：最終採用的做法
- **理由/否決方案**：為何這樣選，放棄了哪些替代方案與原因
```

## 6. `evolve` 的定位——隨時可做的整理，不是排程任務

真正的學習不靠排程，靠兩個已經是 always-on 的機制：任務進行中的即時擷取（§2）、以及每個任務收尾時的「know-how 沉澱三問」（`claude-workflow/WORKFLOW.md` §9，輕軌 L4／標準軌 M4／重軌 R6 都會做一次）。這兩處已經涵蓋「每次對話自動學習重要內容」，不依賴週期提醒。

- `evolve` 是**選配的深度整理工具**：用來對已經累積的多筆記憶做去重、升級、跨檔案校準——這種「發現同類教訓在好幾個地方重複」的模式辨識，適合累積一定量之後一次處理，不代表學習本身是批次的。使用者想整理時執行即可；`MEMORY.md`／`overview.md` 逼近行數上限時，模型可以主動建議執行，但不掛在固定週期或到期提醒上——**不應該有 hook 去提醒或強迫使用者跑它**。
- 完整程序見 `evolve` skill。想留一個「上次整理到什麼時候」的參考點，可選擇性更新 `~/.claude/memory/last-review.txt`，純備忘用途，不是任何機制的觸發依據。
- 專案記憶層的即時收口仍由 `claude-workflow` 的 Stop hook（`knowhow-check.ps1`）機械提醒未沉澱的實質修改，這一支是每次 session 都會檢查，不是週期性的，權威定義在 `claude-workflow/WORKFLOW.md` §9。
- **無 skill 載入能力的 agent**：`learn`／`evolve` 只是操作捷徑；改為直接把本檔 §4／§5 步驟與對應 SKILL.md 當一般文件讀取後手動執行即可，迴圈本身不依賴 skill 機制。

## 7. 誠實性與安全邊界

- 記憶條目是「當下觀察」：引用前必須驗證仍成立；不確定的觀察標註「待驗證」，禁止把未驗證推論寫成事實。
- 進版控的記憶層（如專案 repo 內的 `.agent/learning/`）**禁止寫入任何秘密**（token、密碼、連線字串、個資）；環境變數只記名稱、不記值。全域 `~/.claude/memory/` 雖不進版控，同樣不記秘密值。
- 教訓與規則衝突時，以規則檔與決策紀錄為準，並在下次 `evolve` 時修正該條目。
