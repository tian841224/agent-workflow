# Prompt 教練系統 (Prompt Coach) — 全域

> 教練對象是**使用者本人的 prompt 撰寫習慣**，與 [~/.claude/rules/learning.md](learning.md) 的自我學習迴圈（教練 **AI 自己**的教訓：工具陷阱、流程方法論等）是兩個**平行獨立**的系統，彼此不互相依賴、不共用檔案。設計風格刻意沿用同一套慣例（inbox → 蒸餾 → patterns 上限＋修剪），降低學習成本。

## 1. 目的

比對「使用者最初下的 prompt」與「最終被接受的執行結果」之間的落差，回頭：

1. **直接給出修正後的 prompt 成品**——不是用「建議」語氣描述怎麼改，而是把改好、可直接複製使用的完整 prompt 當作主要交付物。這個修正後版本本身就要同時做到「一次到位」＋「更精準」＋「更省 token」，三者合一，**不拆成分開列點的三份建議**。
2. 落差診斷只是輔助說明（為什麼原本的 prompt 會落差），附在修正後 prompt 之後，不喧賓奪主。

## 2. 落差訊號定義

同一任務內，使用者對 AI 的理解或做法做出以下任一行為，都算一次「落差訊號」——代表原始 prompt 沒把意圖說清楚：

- 修正（「不是這樣」「應該是…」）
- 追問／補充澄清（AI 沒問到但使用者主動補的資訊）
- 否決重來（要求整個重做）

## 3. 兩種觸發模式

### 3.1 自動輕量捕捉（always_on，直接 append，不呼叫 skill）

任務進行中偵測到落差訊號時，**必須在該任務結束前**直接用 Edit/Write 把一行摘要 append 到 `~/.claude/memory/prompt-coach/inbox.md`（格式見 §5.1）。**不做完整分析**，避免每次都燒 token——這一步只是記錄「有落差發生過」，讓之後的整批檢討有素材可用。

即使同一事件也命中 `learning.md` §2 的擷取觸發（AI 該記住的教訓），兩邊分別記到各自的 inbox，不合併、不互相取代。

### 3.2 手動完整分析（呼叫 `promptcoach` skill）

使用者說「檢討這個 prompt」「/promptcoach」「這次結果跟我要的有落差」等，針對單一 case 或整批 inbox 做完整分析，見 §4 輸出格式。

## 4. 完整分析輸出格式（主從兩段，修正後 prompt 為主）

1. **修正後 prompt（直接給成品，放最前面）**——一段可直接複製貼上使用的完整 prompt，已經同時內建「一次到位」「精準化」「省 token」三個目標。
2. **落差診斷（簡短輔助說明）**——原本 prompt 哪裡模糊/缺漏/隱含假設，導致 AI 怎麼猜、猜錯了什麼；只有在有值得使用者記住的可複用技巧時，才多補一句「這次用到的技巧」，不必每次湊滿固定段落數。

若這次分析出的落差類型，在 inbox 或 `patterns.md` 中已出現過同類型 ≥2 次，主動指出「這是你重複出現的 prompt 習慣」，並建議蒸餾進 `patterns.md`。

## 5. 儲存位置與格式

### 5.1 `~/.claude/memory/prompt-coach/inbox.md`（落差訊號，append-only）

```markdown
## YYYY-MM-DD｜任務: <一句話>｜專案: <名稱或 global>
- 原始 prompt 摘要：...
- 落差訊號：使用者做了什麼修正/追問/否決
- 初步判斷落差類型：...
```

### 5.2 `~/.claude/memory/prompt-coach/patterns.md`（蒸餾後的重複 habit，上限 30 條）

```markdown
- **[P-NNN]** <一句話描述 habit>。範例：原始「...」→ 修正後「...」。改善原則：<這個 habit 對應的精準化/省 token 技巧>。（來源: <case 摘要>, 記錄: YYYY-MM-DD）
```

## 6. 批次檢討

觸發：inbox 未處理筆數 ≥5，或使用者要求「檢討我的 prompt 習慣」。

動作：讀 inbox 全部條目 → 比對重複出現的落差類型（查重、可合併就合併）→ 蒸餾進 `patterns.md`（更新表頭「上次蒸餾」「上次回顧」「條目數」）→ 已蒸餾的 inbox 條目移除 → 輸出「你的 prompt 慣性問題＋通用改法」報告。

`patterns.md` 條目數逼近 30 上限時，先修剪過時／已被證偽的條目（同 `learning.md` §4.3 精神：驗證仍成立才保留）。

## 7. 誠實性與安全邊界

- 只能基於本次對話**實際觀察到**的 prompt 原文與實際發生的修正，不得臆測未發生過的情境。
- 目標任務尚未有明確最終結果（任務進行中）時，必須告知使用者「此分析僅供參考，結果尚未定案」。
- 條目不得包含秘密（token、密碼、連線字串、個資）；prompt 原文若含敏感值，摘要時以佔位符取代。
