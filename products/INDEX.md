# 產品配置索引（architect / QA / PM agent 專用）

agent 接到任務時，**先讀這份索引**，從使用者訊息中比對是否提到已註冊產品的代號 / repo 路徑 / URL，找到對應產品後，再 Read 該產品的配置檔載入詳細資訊。**本索引與本機制不寫死任何特定專案的規則內容**——每個產品的實際規格/架構/業務規則都留在該專案自己的文件裡，這裡只登記「去哪裡找」。

## 配置檔設計原則（精簡指標，不重複專案內容）

`products/<product>.md` **只放全域 agent 需要、但該專案自己的文件不會有的操作性質資訊**：

1. **Repo 路徑**：agent 要去哪裡找程式碼
2. **規則入口指標**：該專案自己的 `AGENTS.md` / `CLAUDE.md` / `.agent/rules/` 或至少一份 `README.md` 路徑——實際的技術棧、架構、命名慣例、驗證指令、業務規則，一律去讀這些專案自己的文件，**不在 products 配置裡重複列**
3. **本地啟動指標**：對應 `.claude/launch.json` 的設定名稱（port 以 launch.json 為準，不重複抄）
4. **測試帳號位置**：指向該專案自己的本機檔（例如 `<repo>/.claude/SECRETS.local.md`），**不把帳密寫在 products 配置或任何全域檔案裡**
5. **環境區分**：此產品是否區分 dev / prod？本次標準開發流程設計上到本地驗收為止即停止，不含部署，此欄位僅供未來需要時參考

## 如何新增產品

1. 在 `~/.claude/products/` 建立 `<product>.md`（檔名用 snake_case）
2. 依「配置檔設計原則」填寫，**只放指標，不抄該專案既有文件的內容**
3. 在上方「已註冊產品」表新增一行
4. 不要把產品專屬內容寫進 `~/.claude/agents/*.md`，這些 agent 必須保持產品無關
