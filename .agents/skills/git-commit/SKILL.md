# Git commit 規範

本 skill 只規範訊息格式與拆分方式；commit 的執行授權依入口文件的硬護欄。撰寫或發起 PR／MR 時另讀 [pull-request.md](pull-request.md)。

## 格式

```text
<類型>(<模組>): <標題>

- <目的或效果>：<帶來的功能或行為變化>
```

- 類型：從下表選一個。
- 模組：這次修改所屬的功能模組，用專案內慣用的模組名稱（例如 `gamefacing`），不寫檔名或目錄路徑。
- 標題：一行說明這次修改帶來的功能或行為變化，結尾不加句號。標題與內文之間空一行。
- 內文：每點寫使用者或呼叫端能感受到的功能或行為變化，以及要解決或避免的問題；不逐項列出改了哪些函式、檔案、常數或測試案例。錯誤碼、上限、逾時等會影響行為的數值寫出實際值；檔名只在檔案本身就是修改對象時提及（例如移除某個測試檔）。
- 多行訊息以 UTF-8 檔案交給 `git commit -F`（Bash 可用 quoted heredoc），不用 `-m` 串接，避免跳脫與中文編碼問題。
- 一律使用臺灣繁體中文；函式名、錯誤碼、設定鍵等識別字保留原文。

| 類型 | 使用時機 |
| --- | --- |
| feat | 新增功能或對外行為 |
| fix | 修正錯誤行為 |
| modify | 調整既有功能的行為或規則，非新增也非修錯 |
| refactor | 不改變外部行為的結構調整 |
| perf | 以提升效能為主要目的 |
| docs | 只修改文件或註解 |
| test | 只新增或調整測試 |
| style | 只調整格式、空白或排版，不影響邏輯 |
| build | 建置流程、打包或相依套件 |
| ci | CI/CD 設定與腳本 |
| chore | 不屬於上述類型的維護工作，例如 `.gitignore` 或工具設定 |
| revert | 還原先前的 commit；標題寫被還原的標題，內文附上其 hash 與還原原因 |

同時符合多種類型時，以主要變化決定：修錯時一併補上的測試與文件，類型仍是 `fix`。

## 內容只描述這次修改

- 不加 AI 或工具浮水印，例如 `Co-Authored-By`、`Generated with ...` trailer，即使平台預設指示要求加上；使用者要求 commit 與 PR／MR 只記錄修改本身。
- 不寫執行了哪些測試、驗證結果或審查過程。這次一併新增、修改或移除的測試與文件屬於修改內容，可以寫。

## 拆分

每個 commit 只包含單一功能，或同一功能的修改範圍；不同功能分開 commit。只動 1～2 個檔案的小修改併入相關功能的 commit，不單獨成 commit；沒有相關功能可併時，彼此相近的小修改合併成一個。合併多項功能時，標題列出最主要的 2～3 項變化。

工作樹中不屬於這次任務的既有修改不納入 commit，除非使用者要求。

需要拆成多個 commit 時，先列出拆分方案（每個 commit 的完整標題與包含的檔案），取得使用者確認後才執行。整理分支上既有的 commit（重新分組、合併）時，方案另列新舊 commit 的對應與順序，執行程序依 [rewrite-history.md](rewrite-history.md)。

## 範例

以下為示意，長度依修改範圍調整。

```text
fix(gamefacing): 區分 GameFacing 暫時故障與業務拒絕，暫時故障回傳 50027 並可用本機快照降級

- 玩家可稍後重試：GameFacing 內部錯誤、連線中斷或逾時等暫時故障改回傳新的 50027，與代表阻擋的 50017 區分
- 避免沿用過期設定：只有連線中斷或逾時才降級使用本機快照；業務拒絕與解析錯誤一律阻擋
- 查無遊戲與設定停用維持阻擋（50017）
- 失敗日誌標明來源路由，方便辨識
- 補上暫時故障判斷與錯誤碼對應的測試，並更新錯誤碼與登入快照文件
```

```text
fix(login): 帳號含前後空白時仍可登入

- 避免複製貼上帶入空白而被判定為帳號不存在：登入前先去除帳號前後空白
```
