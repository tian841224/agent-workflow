# Mock 使用指引

## 適合 mock 的邊界

優先只 mock 無法在測試中直接使用或不應真的觸發的外部邊界：

- 第三方 API、付款與寄信服務。
- 時間與隨機性。
- 檔案系統或其他需要隔離的外部資源。
- 無法使用一次性測試資料庫驗證的資料庫操作。

自己的 class、module 與內部 collaborator 通常不應 mock；否則測試會鎖定實作結構，重構時容易在行為不變的情況下大量失敗。

## 讓邊界容易測試

- 以明確介面表達每個外部操作。
- 透過 dependency injection 傳入外部依賴，避免在函式內自行建立難以替換的 client。
- mock 回傳單一且具體的資料形狀，避免在 mock 裡重新實作大量條件邏輯。
- 能使用隔離的真實資源時，優先採用真實資源；仍須遵守 Verifier 對一次性測試資源的限制。
