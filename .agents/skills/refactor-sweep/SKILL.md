# Refactor sweep

刪除、合併、搬移或改名程式碼時，「能編譯、測試會過」不代表收尾完成。被刪掉的東西常留下引用、測試替身、文件與註解；合併相似實作時常順手改掉 log 與錯誤字串；移除中介層時常漏掉它默默做的事。本 skill 是這類修改的收尾程序。

## 1. 動手前

- 列出這次要刪除、合併、搬移或改名的每個識別字。
- 用全文搜尋（例如 `git grep -n '<識別字>'`）找出全部引用，範圍包含：正式程式、測試、測試替身（fake／mock）、文件、註解、設定鍵、以字串形式註冊的路由或反射用名稱。
- 依前面的審計或 review 結果動手時，每一項先在目前程式重新核對；審計之後的 commit 可能已經處理掉，或行號已經移動。

## 2. 合併多份相似實作

- 先產出逐份差異表，不要憑「看起來一樣」就合併。
- 每個差異都要決定：保留成參數或分支，或明列為行為改變。
- log 訊息、錯誤字串、錯誤碼、回應欄位都是行為的一部分；log 字串常被檢索與告警比對，合併時保留原文。

## 3. 移除中介層、包裝或 middleware

- 先列出它的所有副作用：輸入驗證、錯誤回應、log、鎖、重試。
- 每一項決定移到哪裡保留，或明列為行為改變。

## 4. 不引入的寫法

- 不新增「回傳 stop／handled／ready 旗標，讓呼叫端據此提前 return」的 helper；把流程寫成直線。
- 新增的抽象要通過 codebase-design 的 delete test：刪掉它，複雜度會不會在多個呼叫端重新長出來。只有一個呼叫端、只轉呼叫的包裝不要加。

## 5. 完成後

- 被移除或改名的識別字，在程式、測試、文件與註解中搜尋結果為零（刻意保留的要能說明原因）。
- 跑語言的未使用程式檢查，沒有新增項目（Go：`staticcheck -checks U1000 ./...`）。
- 對照修改前的版本，確認合併或移除路徑的 log 與錯誤回應沒有非預期改變。
- 引用到這些識別字、檔名或行號的文件與註解一併更新。
