# Evolve — 週期回顧與記憶蒸餾（全域）

依 `~/.claude/rules/learning.md` §4／§6，對記憶層做一次完整的「蒸餾 → 驗證 → 升級 → 修剪」。可只針對全域，也可含當前專案。

## 步驟

1. **讀取全貌**：讀 `~/.claude/rules/learning.md`、`~/.claude/memory/{inbox.md,MEMORY.md}`；若回顧當前專案，也讀該專案記憶層（repo 內 `.agent/learning/` 或 Claude Code 內建 per-project 記憶）。
2. **蒸餾 inbox**：每條未處理條目改寫為「可操作的一句話＋適用時機」，依 §3 分流併入對應 MEMORY 分區（先查重、可合併就合併）；處理完的條目自 inbox 移除，inbox 恢復為「（目前無未處理條目）」。
3. **驗證 MEMORY**：逐條檢查引用的檔案／指令／行為是否仍成立——用 Read／Glob／Grep 或實際指令確認，**不憑印象**。被證偽的條目刪除；暫時無法驗證的標註「待驗證」。
4. **偵測無效教訓**：檢查是否有「記錄後同類錯誤仍再度發生」的條目（比對近期 git log、inbox 新條目、對話中的反思事件）；命中者視為無效，強制進入升級。
5. **升級（§4.2）**：對重複 ≥2 次或結構性的教訓：
   - rule → 跨專案編輯 `~/.claude/rules/`；專案內編輯該專案規則檔。
   - skill → 跨專案新增／更新 `~/.claude/skills/<name>/`；專案內用該專案 skills 目錄（若有 Codex 同步副本一併更新）。
   - 決策紀錄 → 該專案 ADR／`docs/decisions/` 機制。
   升級後把 MEMORY 原條目刪除或改為一行指標。
6. **修剪**：確保各 MEMORY 條目 ≤50；更新表頭「上次蒸餾」「上次回顧」「條目數」。
7. **回顧報告**：輸出本次結果——蒸餾幾條、合併幾條、升級幾條（到哪些檔案）、刪除幾條、無效教訓清單；有升級動作時逐一列出變更檔案。
8. **提交**：全域 `~/.claude/memory/` 不進版控、不需提交；進版控的專案記憶層變更提示使用者提交（依該專案 commit 規範）。

## 注意

- 驗證步驟（3）是本 skill 的核心，不可省略；沒有驗證的回顧視同未完成。
- 條目不得包含秘密；發現既有條目含敏感值時立即改寫為名稱引用。
