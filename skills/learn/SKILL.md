# /learn — 經驗擷取(自我學習框架:擷取階段)

本技能是自我學習框架的**擷取階段**:把對話中的糾正、決策、偏好、可重用流程、專案知識,分類寫入正確的記憶層,讓之後每個 session 都能受益(召回靠 MEMORY.md 索引自動載入,精煉靠 /evolve 週回顧)。

## 觸發情境

- **自動(被糾正時)**:使用者糾正了你的行為、理解或做法 → 聚焦該次糾正本身,不做全對話回顧,沉澱後繼續原本的工作。
- **自動(決策發生時)**:對話中發生方案轉彎或多選一拍板 → 當下 append 一筆 decision,不等指示。
- **手動(/learn)**:回顧整段對話,萃取所有值得沉澱的內容。

## 步驟

### 1. 萃取

找出要沉澱的內容(糾正、決策、偏好、可重用流程、專案知識)。排除:

- 專案 auto-memory 已涵蓋的內容(先檢查 MEMORY.md 索引)
- repo、git 歷史、CLAUDE.md 已記錄的內容
- 只對本次對話有意義的一次性資訊

### 2. 分類決策樹(三類知識共用)

依序判斷,命中即分類:

1. **被糾正的客觀技術錯誤**(語法錯、API 用法錯、架構行為理解錯)?→ `pitfall`
2. **方案轉彎**(原路不通改走別的)或**多選一拍板**?→ `decision`
3. **工作方式/偏好的指導**(含被糾正的做事方法)?→ `feedback`
4. 其他值得留存的**背景/慣例/資源**?→ `user` / `project` / `reference`
5. 都不是(一次性資訊、repo 已記錄的事)→ **不記**

pitfall 與 feedback 的分界:feedback 是「工作方式與偏好的指導」,pitfall 是「客觀技術錯誤的教訓」。

### 3. 位置判斷(全域 vs 專案)

- 跨專案皆適用(語言偏好、工作習慣、通用流程、工具用法、通用技術坑)→ **全域**
- 僅限本專案(架構、慣例、指令、業務知識、專案特有的坑)→ **專案**
- `decision` 一律放專案 `DECISIONS.md`(決策天然屬於專案脈絡)
- 不確定 → 先放專案,交給 /evolve 週回顧時判斷是否升級全域

### 4. 記憶類與決策類:直接寫入,不需核准

| 內容 | 寫入位置 |
|---|---|
| 使用者個人特質、偏好、習慣 | `~/.claude/USER.md` 對應段落 |
| 全域經驗、通用教訓(含 pitfall) | `~/.claude/memory/<slug>.md` + 在 `~/.claude/memory/MEMORY.md` 加一行索引 |
| 專案經驗、專案知識(含 pitfall) | 專案 auto-memory(路徑見系統提示的 Memory 區段),同格式同索引方式 |
| decision | 專案 auto-memory 的 `DECISIONS.md`,append 到檔尾(檔案不存在就建立,並在 MEMORY.md 索引加指標行) |

記憶檔格式(與內建 auto-memory 一致):

```markdown
---
name: <short-kebab-case-slug>
description: <一行摘要>
metadata:
  type: user | feedback | project | reference | pitfall
---

<內容;feedback/project 類需含 **Why:** 與 **How to apply:**>
```

`pitfall` 類內文模板(三段缺一不可):

```markdown
**錯誤情境:**<當時怎麼錯的:錯誤的寫法/理解,與它造成的後果>

**正確做法:**<修正後的寫法/理解>

**避坑檢查點:**<下次遇到什麼訊號要警覺;可操作的檢查動作>
```

`DECISIONS.md` 條目模板:

```markdown
## YYYY-MM-DD 一句話標題
- **背景**:當時的情境與遇到的問題
- **決策**:最終採用的做法
- **理由/否決方案**:為何這樣選,放棄了哪些替代方案與原因
```

寫入後**必須在回覆末尾回報**:「已沉澱:<一句摘要>(<檔名>)」,並註明可隨時要求撤銷。

### 5. 規則類:列提案,經核准才寫入

要新增或修改全域/專案 CLAUDE.md 的規則時,先列出建議條文與理由,經使用者核准後才寫入。

### 6. 記日誌

在 `~/.claude/logs/<yyyy-MM-dd>.md` 追加一行(UTF-8;檔案不存在就建立):

```
- HH:mm [專案名] 沉澱:<摘要>
```
