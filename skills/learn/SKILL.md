# Learn — 擷取教訓（全域）

依 `~/.claude/rules/learning.md` 的自我學習迴圈，把本次事件的教訓落地。

## 步驟

1. **讀規則與現況**：讀 `~/.claude/rules/learning.md`（§2 觸發、§3 分流、§4 去向、§5 格式）。若本次教訓可能是全域通用，讀 `~/.claude/memory/inbox.md` 與 `MEMORY.md`；若是專案特定，讀該專案的記憶層（repo 內 `.agent/learning/` 或 Claude Code 內建 per-project 記憶）。
2. **釐清事件**：發生了什麼、當時的錯誤假設是什麼、正確做法是什麼。從對話上下文還原；資訊不足時直接問使用者，**不得腦補**。
3. **判斷分流（§3）**：問「這條教訓換一個專案還成立嗎？」
   - 成立 → 全域 `~/.claude/memory/`。
   - 只在此專案成立 → 該專案記憶層（有 repo 內 `.agent/learning/` 用它；否則用 Claude Code 內建 per-project 記憶）。
   - 屬方案取捨／架構決策且該專案有決策紀錄機制（ADR）→ 走該機制，inbox 只記一行指回。
4. **寫入對應 inbox**：依 learning.md §5.1 格式 append 一條（日期、類型、專案、來源、情境、教訓、建議去向）。
5. **立即蒸餾（條件式）**：教訓已明確、可概括、且非一次性瑣事時，直接依 §5.2 格式寫入對應 MEMORY 分區並自 inbox 移除；寫入前先查重（重複則合併並更新日期）。注意 50 條上限與表頭「條目數」同步。
6. **升級判斷**：若這是同類教訓第 ≥2 次出現，依 learning.md §4.2 建議升級成規則／skill／決策紀錄，並在回報中明確提出。
7. **回報**：記錄了什麼、放在哪個記憶層哪個分區、是否建議升級。

## 注意

- 條目不得包含秘密（token、密碼、連線字串、個資）；環境變數只記名稱。
- 不主動 commit；由使用者決定何時提交（進版控的專案記憶層才需提交，全域 `~/.claude/memory/` 不進版控）。
