# 角色交接內容裁剪

分派或切換角色前，以「下一角色完成當前任務所需的最小充分資訊」建立交接 prompt——不傳完整對話背景，也不把無關的規格、實作細節或歷史全部轉交。交接 prompt 不得只寫「請接續處理」；必要證據直接附上，沒有內容的項目標「無」。下一角色發現交接內容與凍結文件或實際證據矛盾時，停止猜測並回報主對話。交接只透過 prompt 傳遞，不新增交接日誌或 acceptance 文件。

依下一角色裁剪：

- **architect**：使用者目標與需求範圍、軌別與階段、相關檔案/模組與既有行為、已確認限制/決策/不可變更契約、已知錯誤與重現步驟，以及本次必須產出的結果。不帶入與實作無關的 QA 探索細節或完整歷史對話。
- **reviewer**：變更目的與 diff 範圍、對應 spec/checklist/mini-spec 條目、pre-review/build/test 結果、已知風險與特別檢查區域、審查回報格式。不帶入尚未發生的 QA 計畫或與 diff 無關的產品背景。
- **qa**：已凍結驗收條目與 cmd/expect、測試前置環境、reviewer/pre-review 結果、需觀察的邊界/錯誤/探索方向、PASS/FAIL/SKIP 回報要求。不帶入不影響判定的實作推導或未凍結的需求假設。
- **pm**：使用者流程與畫面驗證目標、對應 UI 條目與操作步驟、預期畫面/文案/狀態/互動、baseline 與實際差異、需回報的範圍（符合/不符/多做/缺漏）。不帶入程式細節或純後端測試證據。
- **debugger**：完整重現步驟與錯誤輸出、實際資料流與呼叫路徑、已嘗試修法及失敗證據、候選假說與尚未排除的差異、唯讀邊界與預期根因報告格式。不帶入沒有證據的推測結論或已確認無關的路徑。
- **平行 architect subtask**：唯一被分派的檔案/模組範圍、對應 spec/checklist 條目、TDD seam 與驗收要求、已凍結介面與相鄰 subtask 依賴、禁止修改範圍、預期回報格式。
